# `stride-garmin` — the Garmin Connect Personal API client

One long-lived **Personal API Key**, exchanged for a bearer token that is
valid for 24 hours. No developer registration, no OAuth dance, no refresh
tokens.

The reference implementation is `backend/app/ingest/garmin_personal.py`. This
crate is the port of it, and the golden set in `tests/fixtures/` is generated
from the reference's own functions.

## The token lifecycle — the part that bites

* The token is cached with its expiry (23 hours; Garmin issues 24) and reused
  until it is within 60 seconds of expiring.
* **There are no refresh tokens.** "Refreshing" means exchanging the Personal
  API Key again, so the client keeps the key and exchanges it on demand.
* On a **401**: exchange once, retry once. On a second 401:
  `GarminError::NeedsReconnect`, and **no further request is issued**.
* A **403** is a scope failure, not a token problem: `GarminError::Forbidden`,
  never retried.
* Nothing ever loops.

## The key

The Personal API Key is a credential for the athlete's whole Garmin account.

* it never goes in a log, an error message, a `Debug` output or a URL;
* it is passed in by the caller — the Android Keystore on the phone, Key Vault
  on the desktop — and this crate never reads it from the environment;
* it is not written to disk by this crate;
* it leaves the process only as `Authorization: ApiKey <key>`, and only for
  Garmin's own hosts.

`GarminClient::new(key)` is the production constructor. `GarminClient::with_base_url(key, url)`
points the client at a local stub; the host must be one of Garmin's or a
loopback address, and anything else is `GarminError::UntrustedHost`.

## The golden set

`tests/fixtures/expected.json` is **the Python reference's own output**. It is
regenerated by:

```bash
STRIDE_DATA_DIR=/tmp/stride-golden backend/.venv/bin/python \
    crates/stride-garmin/tests/fixtures/make_expected.py
```

The script imports the reference implementation — it does not modify it — and
calls `_canonical_from_detail`, `_as_list`, `_bounded_date_range`,
`_athlete_from_personal`, `zone_model` and the reference's own `activities()`
with its HTTP call replaced by a capture.

`tests/golden_parity.rs` (14 tests) compares the port with that file using the
rule of `docs/core-contract.md` §8. `tests/consumer_compatibility.rs` (5 tests)
makes the calls the shared sync (`crates/stride-api/src/sync.rs`) and the
desktop's router make, so a change here breaks them here first.

## Deliberate differences from the reference

| behaviour | reference | this crate | why |
|---|---|---|---|
| a `403` | re-exchanges the token and retries | fails at once | a scope failure is not a token problem |
| a `429` | retries three times, 2/4/8 s apart | `RateLimited { retry_after_secs }` | `docs/garmin-on-device.md` forbids an immediate retry |
| a failed FIT download | `None` | `FitUnavailable { activity_id }` | a failure is a `Result`, not a silent empty |
| an invalid date | substituted with today | `InvalidDate` | a phone app should not silently fetch a different day |
| `activity_page` dates | clamped to a year | clamped to a year | the same |

Everything else — the clamps, the fallbacks, the defaults, the envelope keys,
the field names and the rounding — is the reference's, and the golden set
proves it.
